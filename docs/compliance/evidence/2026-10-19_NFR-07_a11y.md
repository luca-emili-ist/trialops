## 1. Localisation

**Mechanism** (`packages/shell/src/i18n-core.ts`, `i18n.tsx`). The key of a message is its English text:
`const t = useT(); t('Assigned to')`, variables in braces `t('{n} awaiting review', { n })`. A catalogue maps the English
text to the translation; a missing entry falls back to English, never to a key. The locale is the person's choice
(language switch at the top right of every page and on the sign-in page, stored in this browser under
`trialops.locale`), else the first supported browser language, else English. `<html lang>` follows the locale
(WCAG 3.1.1). Dates use the locale and always show the time zone (`formatDateTime`, rule 11: the server keeps UTC;
signature manifestations keep their fixed `YYYY-MM-DD HH:mm:ss UTC` form, CMP-11).

**Which pages are localised.** The SPEC names sites and subjects as the audience of the Japanese UI. Site staff (PI,
study coordinator, CRA) use: sign-in (TRO-090, TRO-091, TRO-092), platform overview (TRO-001, the landing page), site
network and site detail (TRO-020, TRO-021), tasks and task detail (TRO-030, TRO-031, including the review of agent
proposals and the confirmation of an onboarding plan), not found (TRO-098), SSO hand-off to an app (TRO-041), the shell
(navigation, banner, user area, footer, dialogs, signature and reason dialogs, idle-timeout warning, Suggest changes).
These are in English and Japanese. **Decided by default:** the pages for sponsors, operators and platform administration
stay English-only — arms, protocol and new-arm wizard (TRO-010…013), applications (TRO-040), AI ledger (TRO-050), audit
trail (TRO-051), AI monitoring (TRO-052), pending AI actions (TRO-053), quality, providers, privacy, app validation
(TRO-054…057), change requests (TRO-060), component catalogue (TRO-099). Their shell (navigation, dialogs) is translated.
There is no subject-facing page yet (eConsent and ePRO are apps); when there is, it follows the same mechanism.

Not translated by design: content of records (titles, protocol text, metric names, API error messages), the signature
manifestation and the AI provenance marker (fixed wording of the GxP record, CMP-09/CMP-11), and the default text of a
change reason (it is recorded in the audit trail).

**Completeness is tested** (`[NFR-07]` in `apps/web/test/i18n.test.ts`): every literal `t('…')` of the localised pages
(`apps/web/src/i18n/pages.ts`) and of the shell has a Japanese entry with the same `{variables}`; labels that reach `t()`
through a variable (navigation, activation steps, metric states) are checked by name; catalogues carry the review flag.

## 2. How to localise the EDC pages (M06b) at integration

**Done at the wave D integration (branch `v1-wave-d`, 2026-10-19):** the six EDC pages (CRF library TRO-070, CRF version
TRO-071, data entry TRO-072, casebook TRO-073, visit TRO-074, data queries TRO-075) build their `const T` with `t()`, have
their Japanese entries in `apps/web/src/i18n/ja.ts` (machine-drafted, same review flag), are listed in `SITE_FACING_PAGES`
and are in the route list of `e2e/a11y.spec.ts`. Not translated by design: CRF content (form names, item labels, codelist
decodes, query questions and answers) and the default reason of the CRF approval signature.

The procedure, for later pages:

1. In each site-facing EDC page: `const t = useT();` (from `@trialops/shell`) and wrap every visible text, label,
   `aria-label`, placeholder and toast in `t('English text')`; use `{name}` variables, never string concatenation of
   translated fragments. Format dates with `fmtDate` / `fmtDateTime` of `apps/web/src/format.ts`.
2. Add the Japanese entries to `apps/web/src/i18n/ja.ts` (or a module file `apps/web/src/i18n/edc.ja.ts` merged in
   `apps/web/src/i18n/index.ts` with `mergeCatalogues`), with CDISC/CDASH terms as in the Japanese CDISC CT where one
   exists (rule 13: terminology values themselves come from the dictionary tables, not from the UI catalogue).
3. Add the page files to `SITE_FACING_PAGES` in `apps/web/src/i18n/pages.ts`; `npm test` then fails on any missing
   translation.
4. Add the EDC routes to the route list of `e2e/a11y.spec.ts` (ids of the synthetic seed).

## 3. Japanese texts: machine-drafted

All Japanese strings (`packages/shell/src/i18n/ja.ts`, `apps/web/src/i18n/ja.ts`, ~340 entries) were drafted by Claude
Code and are marked in the header of each file as **MACHINE-DRAFTED — NEEDS REVIEW BY A NATIVE JAPANESE SPEAKER**. Terms
chosen (to confirm in the review): site 施設 / 実施医療機関, principal investigator 治験責任医師, sub-investigator 治験分担医師,
CRA モニター（CRA）, study coordinator 治験コーディネーター（CRC）, arm アーム, randomized 無作為化, signature 署名,
audit trail 監査証跡, reason for change 変更理由, suggestion-only 提案のみ, green light 開始許可. The review should be done by
a clinical operations professional familiar with J-GCP and ERES wording before the UI is shown to Japanese sites.

## 4. Accessibility check

**Method.** `e2e/a11y.spec.ts` signs in as the synthetic platform admin (sees every page), opens **every route** of
`apps/web/src/router.ts` (22 incl. sign-in, component catalogue and not found; ids from the synthetic seed) in **English
and Japanese** at **1440×900 and 375×812**, waits for the data, runs axe-core with the WCAG 2.1 A/AA tags, measures
`scrollWidth − innerWidth` and checks `<html lang>`. 88 page checks per run. A second spec
(`e2e/governance-ui.spec.ts`) drives the new pending-action and AI monitoring pages with the keyboard-reachable controls.

**First run (before fixes, after the i18n change)**: 88 violations, all `label-content-name-mismatch` (serious, WCAG
2.5.3): the accessible name of the page-code button ("Copy the link to this page (TRO-001)") did not start with its
visible text. No contrast, label, landmark, list or ARIA violation was reported; no page scrolled horizontally.

**Fixes made in this change** (shell, so every page benefits):

| Issue | WCAG | Fix |
| --- | --- | --- |
| Page-code button name did not contain the visible code first | 2.5.3 | name = "TRO-001 — Copy the link to this page" |
| No way to skip the navigation | 2.4.1 | skip link "Skip to content" to `main#main` (focusable) |
| Scrollable tables not reachable by keyboard | 2.1.1 | table region focusable (`tabIndex=0`), `role="region"` with a name |
| Focus could leave an open dialog | 2.4.3 | Tab / Shift+Tab kept inside `Modal` (signature and reason dialogs included) |
| Nav count announced only as a label | 1.3.1 | visible count + screen-reader text "waiting" |
| Language of the page | 3.1.1 / 3.1.2 | `<html lang>` follows the locale; options of the language switch carry their own `lang` |
| Copy confirmation and suggestion sent not announced | 4.1.3 | `role="status"` |
| Empty table headers (action columns) | 1.3.1 | headers "Action(s)" |
| Identical "Sign in" buttons in the demo user list | 2.4.6 | named "Sign in as <person>" |

**Result after the fixes** (run of 2026-10-19 on the branch, local stack, synthetic seed): **0 axe violations** on 88 page
checks (22 routes × 2 locales × 2 viewports), **0 pages with horizontal scroll** at 1440 px and 375 px, `lang` correct on
all 88. **After the wave D integration** (EDC routes added): **0 violations on 112 page checks** (28 routes × 2 locales × 2
viewports), 0 horizontal scroll, `lang` correct on all 112. The summary file is regenerated by every `npm run e2e`.

**Limits of the automated check.** axe finds about a third to a half of WCAG issues. Not covered automatically and still to
do by a person (assurance stays *unscripted* as declared): screen reader pass (VoiceOver / NVDA) of sign-in, task review
and signature dialog; zoom to 200% and text spacing (1.4.4, 1.4.12); reflow at 320 px (1.4.10, checked at 375 px only);
focus order on the process map and attention lists; Japanese IME input in the forms; the colour contrast of the AI
iridescent edge is decorative (information also in text).

Also fixed: TRO-030 task filters no longer stretch across the page; TRO-040 catalogue table fits at 1440 px (identity,
class and state stacked in their cells; values wrap) — internal table scroll remains possible on phones by design.
