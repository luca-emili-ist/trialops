# Visual design (TrialOps web)

**Direction A — clinical glass**, chosen by Luca Emili on 2026-10-12 among three restyling mockups (A clinical glass,
B control room, C command and copilot): https://claude.ai/artifact/3HxQmqvcZjXLE5eUuRJEvR. It replaces direction C
"sober regulatory" (2026-10-07, https://claude.ai/artifact/6vEDSczbLeYYwkoVcLZirK), judged not modern enough.

Light frosted surfaces on a cool ice ground. Schibsted Grotesk for compact display titles, IBM Plex Sans for the
interface, IBM Plex Mono for codes, times, versions and labels. **The AI is a material**: content generated by an agent
and not yet signed sits in a panel with an iridescent violet–teal edge (`Panel ai`), its added lines are tinted violet,
and the provenance marker reads "AI" in the same gradient. Cobalt for actions, **green only for actions that sign or
approve**, colour for anomalies only: everything within target stays neutral grey (P3), and every coloured item has a
line saying why (P6).

## References and what we take

| Reference | Why | What we take | What we avoid |
| --- | --- | --- | --- |
| Veeva Vault Clinical | eTMF/CTMS leader, language sponsors know | state, version and signature always beside the content | deep menus, long form screens |
| Medidata (Rave/CTMS) | the reference for study managers | per-site and per-arm tables with thresholds | density without hierarchy |
| Vercel dashboard | clear, precise surfaces with live process state | process map with a live current step, mono labels | pure black as the only option |
| GitHub pull request | the proven way to review a diff | diff by section with +/−, checks, accept/reject | developer jargon |
| Linear / Attio | dense tools people use all day | short rows, states as chips, facts under the title | playful start-up look |
| HP-HMI control rooms (ISA-101 practice) | operators supervising automation | grey is normal, colour only for anomalies | overloaded panels |

## Interfaces for Governed AI (P1–P11) in this direction

- P1 objects: `PageHeader facts` shows state, version and owner as chips under the title (task, arm, protocol).
- P2/P7 process: `ProcessMap` shows the steps, the signature gates and who acts at each step (agent or person, with the
  autonomy in words); an agent step in progress pulses.
- P3/P6 exceptions first: `AttentionList` on the overview lists only off-target measures, each with a reason; the metric
  table stays neutral (`MetricBar tone` only for anomalies; "interim target met" is neutral).
- P4/P5 diff and provenance: `DiffList` inside `Panel ai`, with `AiProvenance`; sources cited beside the proposal.
- P8 friction only at the signature: `SignDialog` (meaning + reason + password + authenticator code).
- P10 history: task history and the audit trail (TRO-051). P11 peripheral layer: `NavItem count/severity` beside Tasks.
- P9 intent bar (draft + diff from a request) is in the mockup but **not built yet**: it needs an API that turns a
  request into a draft task. Open point for a later milestone.

## Where it lives

- Tokens: `packages/shell/src/tokens.css` (colour, type, space, radius, row heights). No value outside this file.
- Components: `packages/shell/src/` — `Button`, `TextField`/`SelectField`/`Field`, `DataTable` (sticky, sortable),
  `Panel` (with `ai`), `PageHeader` (with `facts`), `KeyFigures`, `StatusPill`, `MetricBar`, `Steps`, `ProcessMap`, `AttentionList`, `DiffList`, `DefinitionList`, `EmptyState`,
  `Modal`, `SignDialog` (Part 11: meaning + reason + password, plus the authenticator code when the signer has MFA:
  `SignMfaContext`, IAM-01), `ReasonDialog` (DM-03), `ToastProvider`, `AppShell`,
  `PageFooter` (copyright + page code), `SignatureManifest` (CMP-11: "Signed by name · meaning · UTC time · Reason")
  and `AiProvenance` (CMP-09: "AI-generated by agent (model) · reviewed by name"). The print stylesheet in `shell.css`
  (`@media print`, `.no-print`, `.print-only`) is the PDF export of a page (audit trail review, TRO-051).
- Catalogue: `#/ui` (page `TRO-099`) shows every component in its states.
- Sign-in (TRO-090) has two further steps with their own codes, not routes: TRO-091 authenticator code and TRO-092
  enrolment of a first authenticator (QR code + setup key). The idle-timeout warning is a `Modal` of the session (CMP-03).

## Rules for whoever writes pages (Claude, Forge, Local Dev)

1. Use only the components of `@trialops/shell`. If one is missing, stop and report it in "Open points"; do not invent it.
2. No hex colours, `rgb()` or inline colour/font styles in `apps/web/src` (enforced by `apps/web/test/pages.test.ts`).
3. Every route has a page code in `apps/web/src/pageCodes.ts` (`TRO-xxx`, never reused; tested for uniqueness/coverage).
4. Every GxP change asks for a reason (`ReasonDialog`); every approval or acceptance of an AI proposal is a signature
   (`SignDialog`) with re-authentication. Sign actions use the `sign` button variant, nothing else does.
5. A signature is always shown with `SignatureManifest`, never as a bare id; AI-generated content (proposed or accepted)
   always carries `AiProvenance`.
6. Before a deploy that touches the UI, check every route at 1440px and 375px (no horizontal page scroll).
7. Content from an agent that a person has not signed yet goes in `Panel ai`; nothing else uses the AI edge or the AI colours
   (exceptions: the brand mark, and the current step of a `ProcessMap` when an agent is doing it).
8. Colour means an anomaly or a signature. A state that is normal or on track uses the neutral tone.
